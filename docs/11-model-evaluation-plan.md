# モデルと実音声の評価計画 v0.3

**未実施の試験計画。** contract_labの39テストは状態と原価計算のoffline検証であり、モデル精度・声の品質・本番認証を証明しない。以下の件数・閾値・予算は提案。公式の製品認証条件ではない。

公式[Voice agents](https://developers.openai.com/api/docs/guides/voice-agents)と[GPT-Live評価Cookbook](https://developers.openai.com/cookbook/examples/audio/voice_agent_evaluation)の考え方に沿い、**言った内容、実行した処理、保存された状態、候補者に実際に聞こえた音声**を照合する。

## 比較する順番

| 段階 | データと実行 | 比較対象 | 証明できないこと |
|---|---|---|---|
| 0 契約 | 架空JSON、既存37件＋cache原価2件、schema | 不正形式、世代、失効、原価の二重加算 | モデルの理解・実音声 |
| 1 文字 | [20意図ケース](../contracts/evaluations/dialogue-intents.json)、次の対応、根拠付き要約 | fixed workflow、単発Responses、必要時Decisions | 認識誤り、割込、音声遅延 |
| 2 Crawl | [18シナリオ](../contracts/evaluations/voice-scenarios.json)の該当ケースから固定合成音声 | 旧/新prompt。音声素材とbackend設定を同じにする | 人のマイク・自然な対話 |
| 3 Walk | 同意済みテスターが架空内容を録音。話速、雑音、言い直し | 認識と文字での結果を分離 | 複数ターンの同時発話 |
| 4 Run | 独立した模擬候補者、連続音声、割込・訂正・回復 | 基準構成、必要ならAgentsやchained | 実候補者全体への一般化 |
| 5 人の通し確認 | 実ブラウザー・実マイク・文字代替・review | A01〜A08と操作体験 | 無制限の環境・職種での品質 |

初回は同じケースを各条件3回以上実行し、全件数と失敗例を残す。3回で安全性が証明されるわけではない。holdoutは開発者がpromptを直すためのケースと分け、人が作った追加ケースを投入する。未収集のholdoutを「評価済み」にしない。

連続音声試験で発話ごとに音声時計を止めたり、整然とした交互ターンを強制したりしない。無音も経過時間とLive課金に含める。副次的な同一発話の文字試験は診断として扱い、音声試験の代わりにしない。期待結果・正解ラベル・grader指示は候補者シミュレーターと実行対象へ漏らさない。

## 失敗の数え方と最初の判定案

| 測定項目 | 観測と判定 | 初期gate案 |
|---|---|---|
| 同意・権限・採否境界 | 無同意のprovider開始、他企業情報、auto-finish、採否出力 | 有効試験で1件でも違反すれば停止して修正 |
| 訂正・取消 | 正本、生成世代、late result、再生済み内容を照合 | 古い内容の保存・再生再開があれば不合格 |
| 委譲 | 必要/不要/任意のラベル、実delegation、backend呼出回数 | 必要時の欠落・挨拶時の無駄な呼出を別々に集計 |
| レポート | 全質問、引用ID/revision、要約が根拠から言えるか | ID整合だけで合格にしない。捏造・否定の逆転は不合格 |
| 意図 | ラベル別precision/recall、false finish、missed pause/withdraw | 曖昧ラベルの許容集合も公開。全体accuracyだけで選ばない |
| 音声応答 | 可聴の短い応答と、有用な次質問までを別計測 | 仮目標p50<0.8秒/p95<1.5秒、次質問p95<4秒。SLAではない |
| 割込・無音 | 発話を譲る時間、不要な重なり、待機案内の繰返し、最長無音 | 内容成功と別に人が聴取。改善前後を比較 |
| 公平性・アクセス | 同じ職務回答で話速・アクセント・言いよどみを変えた対照例 | 同じ記録と質問範囲を維持。声から適性推定しない。小標本で公平と断定しない |
| 信頼性 | 接続失敗、欠落、認可失効、30分維持、復旧 | 接続失敗も完了率の分母から隠さない |
| 原価 | Live秒、全backend使用量、cache内訳、再試行、評価用caller/graderの費用 | 面談本体と評価基盤の原価を分ける。budget超過で試験を止める |

評価用録音の破損・ハーネス障害は`invalid_run`とし、製品の不正な動作による`failed`と区別する。予定数、実行数、有効数、無効数と理由を併記し、都合のよい試行だけ集計しない。応答なしは遅延percentileから黙って除外せずtimeout率を別記する。

遅延はクライアントの単調時計と実際の再生を中心に測る。callerの可聴発話終端、delegation受信、backend開始/完了、検証完了、Live append、音声到着、再生開始を関連付ける。異なるマシンの時計の単純減算はしない。応答単位のp50/p95と、runごとの平均値のpercentileを混ぜない。時計対応が不明な測定は不明として残す。

## 証跡とprivacy

各runにcase_id、scenario版、commit、prompt/schema hash、model IDと返却model、tier/reasoning、SDK lockfile、transport、ブラウザー、回線条件、音声素材hash、反復番号を記録する。結果にはapp状態前後、権限判定、ツール/委譲、同期された音声と転記、遅延・usage、失敗理由、reviewer判定を紐付ける。秘密キーは記録しない。

証跡は保護された試験ストレージに保存し、このpublic repoには音声・個人情報を置かない。音声記録への同意は面談機能の同意とは別に扱う。運用の一般ログに本文を残さず、必要な評価データだけ期限とアクセスを決めて保持する。原本に到達できる権限がないgraderへ識別情報を渡さない。

deterministic判定はschema、権限、参照、状態、呼出数に用いる。独立したjudgeは発言の忠実性・自然さの補助だけに使い、人の判定と校正する。人の担当者は自分の下書きを自動採否に変換しない。自由な確認文の有効化、Agents採用、モデル変更は同じセットで比較し、品質を落として速度だけを優先しない。

## 実装者への受け渡し

JSONはこの製品独自のシナリオ定義で、公式ハーネスや旧Evals APIへそのまま渡せる形式ではない。AI担当が公式のCrawl/Walk/Run構成へ変換し、app状態の検査とWebの再生計測を接続する。CIでは現時点で形式・参照だけを検証し、実モデルへの評価ジョブはまだ存在しない。

外部依存の[終了予定](https://developers.openai.com/api/docs/deprecations)を踏まえ、promptはrepoの本文とhashで固定し、評価データは特定APIの保存IDに結びつけない。旧Evals/dashboard、`v1/prompts`、Agent Builderを新規基盤にしない。実API試験の前にproject・キー・許可機能・上限・予算を用意する。
