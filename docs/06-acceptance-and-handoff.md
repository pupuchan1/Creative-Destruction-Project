# 受け入れ条件と引継ぎ

この文書は共有SpaceのA01〜A08、T009を具体化する新提案 v0.2。契約のレビュー前でも架空データのUI・モック接続は進められる。本番APIへの接続、実候補者の試験、外部通知、公開は完了したとは扱わない。[契約モデル](08-contract-lab.md)で検証できた範囲と実サービスの受け入れを区別する。

## 分担案

| 成果物 | 主担当の案 | 接続相手への条件 |
|---|---|---|
| Live/Agents/Decisions/Responses adapter、プロンプト、モデル評価 | AI担当 | 指定イベント・世代・エラー・usageを返す。APIキーはサーバー管理 |
| 同意・面談・字幕・訂正・終了確認・review画面 | Web担当 | 契約にない直接provider操作や採否欄を足さない |
| auth、企業分離、DB、outbox、削除、CSRF | Webバックエンド担当 | AI担当へ認可済みcontextと保存口を提供 |
| fixture、schema、障害シナリオ、日本語接続試験 | 両者 | このリポジトリのcontractを共通基準にする |
| 職務質問・利用説明・保持・pilot/go-no-go | プロダクト/運用責任者 | 誰が承認するかを決める。未決の役割を開発者へ暗黙に移さない |

## 最初の接続手順

1. `contracts/openapi.json`とfixturesをWebのモックへ読み込み、招待交換→同意→文字回答→訂正→終了確認→下書き→reviewを作る。
2. AI担当はprovider-examplesとpromptsをadapterへ接続する。まず完全架空の面談だけで確認し、プロバイダーの生イベントをアプリ契約へ変換する。
3. WebRTCとsidebandを追加。文字回答と同じ正本へ保存し、2接続・再送・後着・訂正を確認する。
4. 実projectのアクセス・region・課金・上限を確認し、実マイクの日本語対話を計測する。結果をこの文書の下の実測欄に追記する。
5. A01〜A08、同意文書、削除、利用規約、担当責任者が揃ってから実候補者pilotの可否を判断する。

## レビューで決めること

| 判断 | 提案初期値 | いつ必要か |
|---|---|---|
| 顧客・職種・採用段階 | 一次面接前の情報収集を仮定 | 質問テンプレートの確定前 |
| 対応端末・ブラウザー | PC Chrome系を最初の計測対象、文字代替を常設 | 音声受け入れ試験前 |
| 最大時間・録音・保持 | 30分、音声原本off、文字30日 | 同意文書とpilot前 |
| コスト/遅延の許容値 | 公開価格から試算、実測で決める | 有料APIの継続試験前 |
| API契約・AI/Web担当・レビュー者 | このv0.1と役割分担を基点に確定 | 並行する本実装の着手前 |
| provider地域・ZDR要否 | US/EU対応とAgents保持を前提に説明 | 実候補者を扱う前 |
| 11/30の完成条件 | A01〜A08を基本とするgo/no-go | 期限の確定前 |

11/30と12月の目安は維持するが、残る論点・担当者・実測結果から範囲を決める。12月のマーケティングは公開・広告費・顧客への連絡を自動的に許可するものではない。
