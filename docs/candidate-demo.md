# 候補者のダミー対話

## 試せる流れ

1. `/candidate/demo` の案内で、このサイトでできることを確認する。
2. 「利用前の確認へ」から、職種とやってみたいことを選ぶ。職種はデザイン、Webエンジニア、マーケティング、未定の4種類。
3. 説明のチェックを入れ、対話画面に進む。
4. 各質問で「ダミー回答を入力」を押す。音声で回答した想定の文章が入り、必要なら編集できる。「この回答で次へ」で確定する。
5. 最後の質問から「要約を確認する」で、受け取った情報と元の回答を見比べる。
6. 内容が違う場合は「この質問をやり直す」でその一問だけ再入力する。「補足する」では回答を残したまま説明を追加できる。補足の編集・キャンセル・削除も可能。
7. 4問に回答したら「この内容で確認を完了する」で完了画面へ進む。「最初からもう一度試す」で選択と回答を初期化する。

## 質問

| 質問                                         | 確認する内容                       |
| -------------------------------------------- | ---------------------------------- |
| どんな仕事をやってみたいですか               | 興味のある職種と、その理由         |
| これまでに取り組んだことを教えてください     | 学校・仕事・個人制作での担当と工夫 |
| チームで働くときに大切にしたいことは何ですか | 相談や意見の違いへの向き合い方     |
| 身につけたいことや挑戦したいことはありますか | これからの学習と希望               |

選択した職種と興味に合わせ、架空の入力例を用意する。`features/candidate/demo.ts` に質問、ダミー回答、要点をまとめている。

## 要約と訂正

ダミー回答には、あらかじめ用意した短い要点を表示する。自分で編集した回答は意味を推測せず、入力文をそのまま表示する。補足は別欄に表示し、元の回答を上書きしない。これは音声認識や生成AIの品質を検証する実装ではなく、要約を確認して直す操作を体験するデモ。

質問のやり直しでは既存の回答を入力欄に戻し、確定した一問だけを更新する。他の回答と、その質問の補足は保持する。職種を選び直しても入力済みの回答を消さず、次に読み込むダミー回答の例を切り替える。

## 保持と未回答

入力は候補者ルートのReact Context内だけで保持する。DB、localStorage、sessionStorageへの保存、外部APIへの送信、マイク使用、録音は行わない。再読み込み、候補者ルートから企業側への移動、「最初からもう一度試す」で消える。

要約画面への直接アクセスや再読み込みでは、未回答の項目を明示し、確認完了ボタンを無効にする。完了画面へ直接アクセスしても、要約確認へ戻す。説明のチェックは画面確認用で、認証や正式な同意記録ではない。

認証、企業への提出、実データ保存は別の実装範囲。企業側の架空面談記録とは同期しない。
