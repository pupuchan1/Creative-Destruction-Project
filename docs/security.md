# セキュリティと現在の実装境界

## この段階で実装したこと

- Node.js 24.22.1を固定し、24.22.1未満と24系以外はインストール・開発時に拒否します。公式配布のSHA256と公式セキュリティ告知を確認したバージョンです。
- 依存は正確なバージョンとlockfileで固定します。CIで `npm ci` と開発依存を含む `npm audit` を実行します。
- FEは外部APIを呼ばず、秘密鍵・実候補者データ・外部フォントや解析タグを含めません。音声やマイクにもアクセスしません。
- Honoの `/api` と `/api/*` は全メソッドで503の共通JSONを返し、`Cache-Control: no-store` を設定します。認証がない状態でデータを提供しません。
- 配信時にCSP、フレーム埋め込み拒否、nosniff、Referrer-Policyを設定します。カメラ・マイク・位置情報はPermissions-Policyで拒否します。
- 開発サーバーはloopbackのみで待ち受けます。Viteの開発サーバーは本番公開用ではありません。
- `.env`、`.dev.vars`、ビルド成果物はGit管理から除外します。開発に秘密情報は不要です。

## 本番接続前に必要なこと

1. HTTPSを強制し、TLS 1.3優先・最低TLS 1.2、証明書検証と更新、HSTSを配信基盤で設定・検証します。今回のローカルHTTP確認はTLS対応の完了を意味しません。
2. Supabase等の認証、管理者MFA、HttpOnly・Secure・SameSite Cookie、セッション失効、CSRF対策を実装します。サンプル画面には認証境界がありません。
3. 各操作の企業と役割をサーバーで検証し、PostgreSQLのRLSを適用します。管理キーによる全権限アクセスを通常処理に使いません。DB接続はTLSと証明書検証を有効にします。
4. 期限・失効付きの招待と短命な音声接続認証を実装します。長期APIキーはサーバーのSecret管理に保存します。
5. 音声接続時に限りPermissions-PolicyとCSPの接続先を許可リストで変更し、同意後にWebRTCを開始します。現在の拒否ポリシーは意図的です。
6. 非公開Storage、必要な保存時暗号化、同意、保持削除、監査ログ、バックアップと復元、API利用量の上限を検証します。

## 更新時の確認

固定したNodeや依存パッケージにも将来脆弱性が見つかり得ます。DependabotのPRと [Nodeのセキュリティ告知](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases) を確認し、テストを通して更新してください。`npm audit` はNode本体の脆弱性や認可設計の欠陥を検出するものではありません。

## 外部サイトからの受検

企業サイトに置くモジュールはHaaSの公開案内への通常のリンクです。iframeを使わず、フレーム埋め込み拒否は維持します。公開カードへ個別招待・候補者情報・秘密鍵を含めません。本番の招待はサーバーで検証して短命セッションへ交換し、戻り先は企業が登録したHTTPS URLの許可リストで管理します。提出APIにはCSRF・所有企業の検証・冪等性・受領確認を実装します。詳細は [構成案](architecture.md) を参照してください。

現在の2社の画面設定と招待IDは架空サンプルで、サーバー側の認証や企業間分離を代替しません。回答の企業間引き継ぎを防ぐ一時状態の分離だけを実装しています。提出・招待発行・ATS連携は未接続です。
